# 良子小窗的扩展边界

## 应用入口与模块

`AppController` 管理托盘、主题和整体退出；`IWindowModule`/`WindowModule` 管理模块标识、入口文字、窗口工厂、打开和释放。
当前注册 reading 和 chat 两个模块。子模块只提供返回主页的导航入口；新增模块不在其他子模块内增加直达按钮，托盘也统一返回主页。新增工具时注册独立模块，由入口自动生成按钮；不要把新功能直接堆进阅读窗口。
打开与关闭子模块不改变主菜单可见性；阅读和聊天只共享 Store 中的偏好，不持有对方窗口。聊天通过保存设置、返回主页两个回调与入口交互。
`LibraryForm` 的单独构造模式用于兼容阅读测试；正式程序由 AppController 管理。

阅读关闭时保留隐藏的书架控制器以维护已有热键，释放当前 ReadingSession 和悬浮阅读窗口；再次打开时按保存位置重建正文。
聊天关闭时释放窗口、计时器、连接、接收队列和正文。隐藏只改变可见性。
所有 Store 写入均在客户端 UI 线程完成；独立服务只读主题文件，禁止服务回写阅读状态。

## 协议与消息类型

协议采用 TLS 保护的 TCP 流，消息外层有 4 字节长度限制，正文 XML 禁止 DTD 和外部实体。
`ChatPacket.Version = 2`；不兼容版本直接拒绝。`ContentType` 当前仅支持 text；未知类型给出错误，不伪装成普通文字执行。
`Kind` 表达加入、发送、心跳、状态等操作。服务器确定发送者、会话和消息序号，不信任客户端提交的同名字段。

添加图片/附件时，需要同时实现类型校验、单文件与房间总容量、传输分块、存储寿命和客户端显示。
不要仅增大 MaxFrame 或把无限大小的图片 Base64 塞进文字协议。附件应放入独立传输与缓存模块，并关联受校验的消息标识。
链接的文本内容现在可以传输；后续点击与预览应只允许明确的协议和用户动作，不能自动打开未知链接或下载资源。

## 容量和内存

`ChatOptions` 集中定义默认历史、客户端显示、在线人数、消息长度、握手连接、发送队列和发送频率；可在创建 ChatServer/ChatForm/ChatConnection 时注入选项。
选项有硬上限，协议帧上限也独立校验。未来增加设置界面时复用同一选项校验，避免只改界面数值。
接收由网络线程投递有界队列，UI 定时批量读取，避免每条消息都排入一个无界窗口回调。
服务对慢连接使用有界发送队列，满时断开。历史与发送队列只持有数量受限的消息引用。
停止服务显式清空历史、连接及限流表；关闭客户端清空本机缓存，.NET 稍后回收其内存。
不要用频繁 GC.Collect 或设置工作集来伪装内存降低。

## 连接安全

默认仅 TLS 1.2，没有明文回退。使用 SHA-256 指纹钉扎自签名服务证书，在 TLS 握手成功之前不发送房间码。
证书每次服务进程启动生成，同一窗口内停止/重启仍使用同一证书。
关闭后重开服务会换证书，客户端需通过可信渠道重新获得指纹。这样无需安装根证书或信任首次未知连接。
Windows .NET Framework 的 Schannel 需要用户密钥容器；证书导入不指定 PersistKeySet，不将其装进信任库，不生成外部 PFX 文件。

未来统一证书或身份系统应替换 ChatSecurity 和加入验证部分，保留房间限流、消息长度与队列上限。
加密只覆盖传输，服务器能看到消息，昵称不是身份认证；账号和审计需独立设计。

## 验证和限制

1.5.2 的 Shell.Tests.cs 覆盖主菜单可见/隐藏两种状态，验证子模块打开、关闭、重复打开均不改变主菜单；仅明确整体退出才结束应用。

test.ps1 验证阅读回归、真实 TLS 连接、协议、安全校验、缓存和模块关闭。测试只绑定本机回环地址，不启动公司网络上的房间。
真实跨电脑连通性、企业证书策略、不同 DPI/显示器、长时间运行负载和独立安全审计仍需后续验证。
当前构建不使用外部依赖；两个 EXE 都以 .NET Framework 4.8 为运行要求。
